## 一、系统架构与关键环境变量

### 1.1 CDN 分层

```
GCS Raw Bucket   ←──── 存 mcap / mp4（原始）
      │
      ├── [Raw CDN]  DATA_RAW_CDN_BASE_URL
      │       用于程序化下载，需 Cloud CDN Signed Cookie 鉴权
      │       URL 形如：https://raw-data.cdn.example.com/{对象路径}
      │
GCS Derived Bucket ←── 存转码后 .mp4 + preview.jpg（衍生）
      │
      └── [Derived CDN]  DATA_DERIVED_CDN_BASE_URL
              用于前端预览视频 / 预览图，公开（或通过 signed URL 回退）
              URL 形如：https://derived.cdn.example.com/{对象路径}

User Management Preview Bucket ←── 存 Tele-Op 预览视频
      └── [Preview CDN]  PREVIEW_CDN_BASE_URL
              通过 preview_video_helper.py 生成公开访问 URL
```

### 1.2 `DATA_RAW_CDN_BASE_URL` 说明

- **含义**：面向客户端的 Raw 数据 CDN **根地址（origin）**，不是具体文件 URL，也不是 `gs://` 路径。
- **格式要求**：
  - 协议为 `http` / `https`（生产必须 `https`）
  - 只允许 **scheme + 主机（及可选端口）**，无路径、无 query `?`、无 fragment `#`
  - 末尾 `/` 会被代码 `rstrip` 掉
- **拼接方式**：`{DATA_RAW_CDN_BASE_URL}/{GCS 对象路径}?{追踪参数}`
- **配合 Signed Cookie**：下载文件时请求头需携带 `Cloud-CDN-Cookie`（由 `/v1/data/download-sessions` 响应中的 `auth` 字段提供）
- **与 `DATA_DERIVED_CDN_BASE_URL` 的区别**：

| 变量 | 资产类型 | 鉴权方式 | 使用场景 |
|------|----------|----------|----------|
| `DATA_RAW_CDN_BASE_URL` | 原始 mcap / mp4 | Cloud CDN Signed Cookie | 程序化 API 下载 |
| `DATA_DERIVED_CDN_BASE_URL` | 转码后 .mp4 / preview.jpg | 公开或 GCS Signed URL 回退 | 前端预览视频 / 缩略图 |
| `PREVIEW_CDN_BASE_URL` | Tele-Op 预览视频 | 公开 | User management 预览 |

### 1.3 CDN 的角色与作用

在本功能中，**用户下载数据走的是 CDN，而非直连 GCS Bucket**。不同场景的路径如下：

| 场景 | 下载路径 | 说明 |
|------|----------|------|
| **API 程序化下载**（本次新功能） | 用户 → **Cloud CDN** → GCS | CDN 必须配置，未配置直接 500 |
| UI 手动下载（旧功能） | 用户 → **GCS Signed URL** | 直连 GCS，不经过 CDN |
| 预览视频 / 缩略图 | 用户 → **CDN**（有配置） 或 GCS Signed URL（兜底） | CDN 优先，未配置降级 |

**CDN 在程序化下载中承担三个核心角色**：

**① 鉴权代理（最重要）**  
GCS Raw Bucket 不对外公开，直接用 GCS Signed URL 需为每个文件单独签名，且 URL 泄漏即可使用。Cloud CDN 改用 **Signed Cookie** 方案——一个 Cookie 覆盖一个路径前缀下的所有文件，CDN 边缘节点验签后放行，否则 403。Cookie 格式为：
```
Cloud-CDN-Cookie=URLPrefix=<base64(url_prefix)>:Expires=<unix_ts>:KeyName=<name>:Signature=<HMAC-SHA1>
```

**② 传输加速**  
mcap 单文件可达数百 MB 至 GB 级，CDN 边缘节点缓存后离客户端更近，降低跨地域延迟，同时减少 GCS 出口带宽费用（CDN 出口通常更便宜）。

**③ 下载追踪**  
CDN URL 附带 tracking query params（`download_id`、`package_id`、`user_id`、`episode_id`、`asset`），可被 CDN 访问日志捕获，用于统计下载行为。参数本身不影响 CDN 缓存和文件内容。

| | GCS Signed URL | Cloud CDN Signed Cookie |
|--|--|--|
| 粒度 | 每文件一条 URL | 一个 Cookie 覆盖路径前缀下所有文件 |
| 传输 | 直连 GCS | 经 CDN 边缘缓存 |
| 过期后 | URL 失效 | CDN 返回 403 |
| 追踪 | URL 参数 | URL 参数 + CDN 日志 |

**④ CDN 缓存命中分析**

CDN 有缓存时客户端直接从边缘节点取文件，不再回源 GCS：

```
Cache Miss（第一次）：客户端 → CDN 边缘节点 → 回源 GCS → 缓存到边缘节点 → 返回客户端
Cache Hit（后续）  ：客户端 → CDN 边缘节点（直接返回，GCS 完全不参与）
```

但对于本功能（程序化 API 下载），缓存命中率实际很低。原因是 CDN 默认以**完整 URL（含 query string）** 作为缓存 key，而 CDN URL 带有 tracking params：

```
https://raw-cdn.example.com/data/ep.mcap?download_id=42&user_id=5&episode_id=101&asset=mcap
```

每次下载 `download_id`、`user_id` 不同 → 缓存 key 不同 → **几乎无法命中缓存**。

| 场景 | 缓存命中可能性 | 原因 |
|------|--------------|------|
| 同一用户重复下载同一文件 | ❌ 低 | `download_id` 每次新建，缓存 key 不同 |
| 不同用户下载同一文件 | ❌ 低 | `user_id` 不同，缓存 key 不同 |
| 预览视频 / 缩略图（Derived CDN） | ✅ 高 | URL 无 tracking params，同一文件 URL 固定，缓存效果好 |

**结论**：程序化 API 下载中 CDN 的核心价值是**鉴权代理**（Signed Cookie）和**边缘节点出口带宽**，而非缓存命中。真正受益于 CDN 缓存的是预览视频 / 缩略图等 URL 固定、高频访问的 Derived 资源。

## 二、数据流分析

### 2.1 Flow A：前端预览（视频 + 静态图）

```
用户打开 Workspace / Admin
        │
        ▼
前端批量请求预览 URL（每次可见 episodeId 触发）
GET /data/downloadable-upload-previews
        │
        ▼
后端 _list_public_derived_media(storage_client, row_data, ttl_seconds)
  ├── 遍历 derived bucket 下该 episode 前缀的所有 blob
  │     ├── blob.name 以 .mp4 结尾
  │     │       → _build_derived_url(blob, ttl_seconds)
  │     │         ├── build_derived_cdn_url(blob.name)   ← 优先 CDN
  │     │         └── 否则 GCS Signed URL（1天）
  │     │       → 追加到 videos[]
  │     │
  │     └── basename(blob.name) == PREVIEW_IMAGE_FILENAME（默认 preview.jpg）
  │             → _build_derived_url(blob, ttl_seconds)
  │             → 赋值 preview_image_url / preview_image_url_type
  │
  └── 返回 { videos, preview_image_url, preview_image_url_type }
        │
        ▼
响应 JSON：
  {
    "episode_id": 123,
    "preview_video_url": "https://derived.cdn.example.com/...",   ← pick_preview_video_url(videos)
    "preview_image_url": "https://derived.cdn.example.com/.../preview.jpg",
    "preview_image_url_type": "cdn"
  }
        │
        ▼
前端缓存到 episodePreviewUrls / episodePreviewImageUrls（按 episodeId 索引）
        │
        ▼
渲染规则（VIDEO_PREVIEW_ACTIVE_COUNT = 4）：
  episodeIndex < 4 且 previewVideoUrl 存在  →  <video>
  episodeIndex >= 4 且 previewImageUrl 存在 →  <img>（懒加载）
  否则                                      →  占位色块
```

### 2.2 Flow B：API 程序化下载（Signed Cookie）

```
① POST /data/api-keys  (JWT)
   → 生成 pxa_... 明文（仅返回一次），存 SHA256 hash
   → 响应: { api_key, key_prefix, status: "ACTIVE" }

② POST /data/api-packages  (JWT)
   Body: { selected_episode_ids: [101,102,...] }
   → 校验 episode DERIVED_READY，估算 total_bytes
   → 响应: { package_id: "pkg_...", episode_count, total_bytes_estimated }

③ POST /v1/data/download-sessions  (X-API-Key)
   Body: { package_id: "pkg_..." }
   → 校验 key hash、package 归属与状态
   → 遍历 GCS 构建 CDN URL（mcap + mp4），生成 Signed Cookie
   → 写 data_downloads READY
   → 响应 manifest（详见第五节）

④ 客户端脚本
   for each sample → for each asset:
     GET asset.url  +  Cookie: <cookie_header>
     → Cloud CDN 验签 → 200 + 文件流
```

> 接口详细逻辑见第五节。

## 三、`POST /v1/data/download-sessions` 接口逻辑详解

### 3.1 HTTP 层

```
POST /v1/data/download-sessions
X-API-Key: pxa_...
Content-Type: application/json

{ "package_id": "pkg_..." }
```

- **鉴权方式**：**仅** `X-API-Key`（不需要 gateway JWT）；header key 大小写不敏感（`X-API-Key` / `x-api-key` 均可）。
- **错误映射**：

| 异常类型 | HTTP 状态 | 典型原因 |
|----------|-----------|----------|
| `PermissionError` | **403** | package 不存在 / 不属于该 key 的用户 |
| `ValueError` | **400** | `package_id` 为空 / package 状态不是 ACTIVE / package 内无 episode / 构建后无可下载文件 |
| `RuntimeError` | **500** | CDN 环境变量未配置（如 `DATA_RAW_CDN_BASE_URL` 缺失） |
| 其他未知异常 | **500** | 记录 `logging.exception`，返回异常消息 |

---

### 3.2 鉴权：`_require_data_api_key()`

```
请求 Header X-API-Key: pxa_...
    │
    ▼
hash_api_key(raw_key) = SHA256(raw_key)   ← 明文永不入库
    │
    ▼
SELECT FROM data_api_keys
  WHERE key_hash = :hash
    AND status = 'ACTIVE'
    AND revoked_at IS NULL
    │
    ├── 无结果 → 401 "invalid API key"
    │
    └── 找到 → UPDATE last_used_at = NOW()
             → 返回 { api_key_id, user_id, key_prefix, status }
```

---

### 3.3 核心函数：`_create_api_download_session(api_key, package_id)`

#### 阶段一：校验与预插入（DB 事务 1）

```
① package_id 非空校验

② get_raw_cdn_config()
     读取 DATA_RAW_CDN_BASE_URL / KEY_NAME / KEY / TTL
     任一缺失 → RuntimeError → HTTP 500

③ SELECT data_api_packages WHERE package_id = :id LIMIT 1
     不存在         → PermissionError "package not found" → 403
     user_id 不匹配  → PermissionError "package does not belong to this API key" → 403
     status != ACTIVE → ValueError "package is not active" → 400

④ SELECT data_api_package_episodes + JOIN data_episodes + LEFT JOIN data_tasks
     无 episode → ValueError "package has no episodes" → 400
     路径优先级：package_episodes 里的 raw_mcap_path / raw_bucket
                > data_episodes 里的字段
                > 默认 DATA_RAW_BUCKET 环境变量

⑤ INSERT data_downloads
     mode = 'api_cdn'
     status = 'PENDING'             ← 先占位，后续若失败会更新为 FAILED
     manifest_version = 2
     auth_type = 'cloud_cdn_signed_cookie'
     expires_at = now + CDN_TTL_SECONDS
     → 返回 download_id
```

#### 阶段二：GCS 遍历 + 构建资产（`_build_cdn_sample_payload`）

```
for row_data in episode_rows:
    ①  raw_bucket.get_blob(raw_mcap_path)
           mcap 不存在 → 跳过该 episode（不报错，但不进入 samples）

    ②  assets["mcap"] = {
            path: raw_mcap_path,
            relative_path: "{episode_key}.mcap",
            url: CDN_BASE/{raw_mcap_path}?download_id=&package_id=&user_id=&episode_id=&asset=mcap,
            size_bytes: blob.size
        }

    ③  list_blobs(raw_bucket, prefix=raw_video_folder_path)
           仅保留 .mp4 且通过 _map_public_video_slot() 得到 slot 的文件
           slot 决定 asset key（如 cam_left、cam_right 等）
           assets[slot] = {
               path, relative_path: "{episode_key}/{basename}.mp4",
               url: CDN_BASE/{blob.name}?...&asset=<slot>,
               size_bytes
           }

    ④  返回 { episode_id, episode_key, task_id, task_name, data_format, assets,
              total_bytes, object_names }
           object_names = [mcap_path, mp4_path_1, mp4_path_2, ...]
```

> **注**：tracking params（`download_id`、`package_id`、`user_id`、`episode_id`、`asset`）以 query string 形式附在 CDN URL 后，用于后端统计哪些文件被下载。

#### 阶段三：Signed Cookie 策略（关键分叉）

```
root_url_prefix = CDN_BASE_URL + "/"     ← 整个 bucket 的根前缀

for each sample:
    sample_cookie = build_signed_cookie(object_names=all_assets)
      └── url_prefix = os.path.commonprefix(object_names) 截断到最后一个 "/"
              e.g. object_names = ["data/ep001/ep001.mcap", "data/ep001/cam_left.mp4"]
                   → url_prefix = CDN_BASE/data/ep001/
              e.g. object_names 无公共路径
                   → url_prefix = CDN_BASE/    (= root_url_prefix)

    if url_prefix != root_url_prefix:
        ✅ 整个 sample 共用一个 Cookie（覆盖该 episode 目录前缀）
           sample["auth"] = { type, cookie_name, cookie_header, url_prefix }

    else:
        ⚠️ 公共前缀退化为 root → 分散到每个 asset 单独签名
           for each asset:
               asset["auth"] = build_signed_cookie(object_names=[asset.path])
```

**意义**：公共前缀越长，Cookie 覆盖面越窄，安全性越高；当对象分散在 bucket 各处时退化为 per-asset Cookie，保证每个文件有独立授权。

#### 阶段四：收尾

```
if samples 为空（所有 episode 的 mcap 都不存在）:
    UPDATE data_downloads SET status = 'FAILED'
    raise ValueError → HTTP 400

否则：
    manifest_payload = {
        manifest_version: 2,
        download_id, package_id, mode: "api_cdn",
        data_format: "mcap/mp4",
        created_at, expires_at,          ← expires_at 取最后一个 Cookie 的到期时间
        auth: { type: "cloud_cdn_signed_cookie", scope: "sample_or_asset" },
        samples: [...]
    }
    UPDATE data_downloads SET status = 'READY', episode_count, total_bytes
    return manifest_payload
```

| 层级 | 覆盖范围 | 建议手段 |
|------|----------|----------|

| 回归 | 历史下载功能、QA Review 预览、`formatHistoryDataFormat` | 手工冒烟 |

### 4.3 风险项

| 风险 | 说明 |
|------|------|
| **密钥明文安全** | 创建 Key 时明文仅出现一次；确认日志无明文泄漏；生产需有 rotate 流程。 |
| **Cookie 过期** | TTL 默认 86400s（1天），到期后 CDN 返回 403；下载脚本需处理此情况。 |
| **list_blobs 性能** | 大 Package（百 episode）创建会话时 list_blobs 耗时可能超时；需关注响应时间。 |
| **前端并发请求** | 初始化时并行 +2 个请求（keys + packages），弱网下需确认不影响主数据加载。 |
| **CDN 未配置回退** | `DATA_DERIVED_CDN_BASE_URL` 为空时派生预览应退回 GCS Signed URL，不能 500。 |

### 7.2 用返回的 Cookie 下载文件

拿到 manifest 后，按 `asset.auth.cookie_header` 设置 Cookie 请求对应 URL：

**curl**

```bash
curl -o ep101.mcap \
  -H "Cookie: Cloud-CDN-Cookie=URLPrefix=...:Expires=...:KeyName=...:Signature=..." \
  "https://raw-cdn.example.com/bucket/path/ep101.mcap?download_id=123&..."
```

**Python（完整下载脚本，见 `QA_Download/download.py`）**

```python
import os
import requests

api_key = "pxa_your_api_key_here"
package_id = "pkg_your_package_id_here"
output_dir = "./dataset"

session = requests.post(
    "https://data.prismaxserver.com/v1/data/download-sessions",
    headers={"X-API-Key": api_key},
    json={"package_id": package_id},
).json()["data"]

for sample in session["samples"]:
    sample_cookie = sample.get("auth", {}).get("cookie_header")
    for asset in sample["assets"].values():
        cookie = asset.get("auth", {}).get("cookie_header", sample_cookie)
        if not cookie:
            raise RuntimeError("missing Cloud CDN cookie for asset")
        target = os.path.join(output_dir, asset["relative_path"])
        os.makedirs(os.path.dirname(target), exist_ok=True)
        with requests.get(asset["url"], headers={"Cookie": cookie}, stream=True) as r:
            r.raise_for_status()
            with open(target, "wb") as f:
                for chunk in r.iter_content(chunk_size=1024 * 1024):
                    if chunk:
                        f.write(chunk)
```

> **注意**：`api_key` 明文不要提交到版本库，测试完毕后及时通过 `DELETE /data/api-keys/<id>` 撤销。
